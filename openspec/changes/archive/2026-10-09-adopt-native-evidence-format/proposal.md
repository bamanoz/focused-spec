## Why

The evaluated native-ID workflow keeps behavior in the host's checkable item and evidence in an identity-only registry, while the production CLI still requires duplicate Markdown focused scenarios. Promote the evaluated format to the sole executable contract without weakening binding, selected-scope isolation, or real runner evidence.

## What Changes

- **BREAKING**: config version 3, required `.focused-spec/evidence.yaml`, native Markdown markers, Gherkin scenario tags, and explicit external native-ID bindings replace inline focused ID/EVIDENCE rows.
- Parse structural native item boundaries using CommonMark and official Gherkin ASTs. Leave behavioral meaning and host-format validity to native workflows.
- Resolve each registry occurrence uniquely within its configured scope; reject detached/duplicate markers, dangling or ambiguous registrations, unknown fields, missing evidence, unsafe paths, and obsolete format.
- Remove WHEN/THEN cardinality assumptions and guessed unenrolled native-scenario counts. Preserve runner API, concrete/planned evidence policy, scoped results, and selection flags.
- Migrate every live caller, behavioral fixture, example, public skill, documentation page, capability spec, and black-box eval. Preserve archives, saved evals, host approval protocols, and generated-source constraints.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `scenario-authoring`: native item identity and evidence-only registry.
- `project-configuration`: version-3 native-document layouts and registry loading.
- `validation`: unique binding and registry/evidence validation rather than host behavioral shape.
- `cli-help`: native-format help and truthful registered coverage.
- `scenario-execution`: existing selections execute bound registry evidence without native-count claims.
- `distribution`: packed consumers execute the native format.
- `agent-workflow`: production native-ID workflow and real packaged CLI evals.

## Impact

Changes source/public models, parser dependencies, discovery, CLI counts/help, skill and docs, shipped examples, tests, eval setup/gates, and repository-native evidence. Runner plugins and scheduling remain unchanged. No package version bump or release is requested.
