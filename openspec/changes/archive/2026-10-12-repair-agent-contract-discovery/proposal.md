# Proposal

## Why

Three fresh public evaluations failed despite working evidence: upgrade guidance was concatenated with unrelated JSON output, and two agents searched installed runner implementation after public README discovery failed. Repair the discoverable public contract and instruction-acquisition guidance without weakening gates or rewriting historical results.

## What Changes

- Require standalone protocol guidance acquisition in the existing loader and portable upgrade workflow.
- Stage the existing human-facing runner guide into each official runner package as its generated README, with source-independent reference links. Keep one authored owner, not three new documentation sources.
- Direct contract research to public README/types and the installed CLI runners topic rather than implementation inspection.
- Exercise documentation-derived selectors from independently packed runners and rerun all nine public cases and fourteen native modes.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `distribution`: official runner consumers can discover selector/options contracts from their installed package without reading implementation.

## Impact

Existing loader/workflow/runner guidance, runner guide, asset staging and runner package inventories; consumer distribution evidence and black-box evaluations. No API/configuration changes, publication, commits, tags or pushes. Retain existing strict protocol, integrity and immutable-result contracts. Native unavailable validators/lifecycle checks remain accurately unverified, not manufactured passes.
