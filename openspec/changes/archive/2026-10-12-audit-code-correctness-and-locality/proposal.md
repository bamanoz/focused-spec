# Proposal

## Why

A complete read-only review of production packages, evaluation tooling, tests, examples and build scripts found contract violations in identity binding, exact framework execution, process lifetime, protocol validation and black-box judgment. Correctness repairs and a narrowly measured planner refactor are needed; superficial restructuring would not address these failures.

## What Changes

- Reproduce and repair cyclic configuration options, harmless leading `./` scope capture, and distinct native items sharing one source line.
- Bound runner settlement independently of inherited pipes, validate IPC envelopes, and reject duplicate CLI options consistently with init.
- Execute exact Vitest task identities without lossy full-name flattening; preserve streaming UTF-8 output in all official runners.
- Enforce Markdown heading/inline-list placement and adjacency against the actual following native item.
- Remove retired generated assets/output when rebuilding, retaining the existing authored owners and independent package inventory.
- Strengthen eval sensitivity, exact agent execution, path consent, proposal-phase integrity, timeout persistence/cleanup, configured working scopes, implementation-inspection checks, immutable persistence and last-phase diagnostics. Preserve blind prompts and historical scores.
- Replace quadratic planner accumulation/search with local selector indexing without changing results or public interfaces.

## Capabilities

### New Capabilities

None. Existing capability owners cover these outcomes.

### Modified Capabilities

- `project-configuration`: cycle-safe JSON options and equivalent harmless-relative scope layouts.
- `scenario-authoring`: item identity independent of source-line coordinates and strict Markdown placement/adjacency.
- `runner-protocol`: bounded host cleanup, validated envelopes, exact Vitest execution and lossless streamed output.
- `cli-help`: repeated options are argument errors, preserving explicit-help precedence.
- `distribution`: rebuilding stages only current owned generated package contents.
- `agent-workflow`: strict, phase-correct, exact and immutable evaluation results, including failures and lifecycle diagnostics.

## Impact

Production changes remain within their existing workspace packages; config version 4, plugin API version 1, declared exports and selector syntax remain unchanged. Eval-only helpers may deepen shared process/result/transcript seams where several independent callers need the same contract. Tests reproduce observable failures before fixes and retain only meaningful regression checks. Update existing documentation owners, sync/archive the change and run surviving evidence. This request does not authorize another release, version bump, commit or push; existing published 0.9.0 and historical eval artifacts are not modified.
