# Proposal

## Why

Block 6 still lacks native-run token measurements, a reusable cross-case guidance-loading report, primary-source grounding for surveyed host extension/context-file claims, and independently exercised native verification where supported. The recorded passing authoring/evidence matrix does not close these gaps or certify unavailable host operations.

## What Changes

- Record native authoring, planning/dialogue continuation and lifecycle agent measurements using the existing public-harness measurement semantics, keeping test-user and diagnostic work separate.
- Add a read-only report over explicitly selected immutable public/native results and invocation records. Report loader/workflow/host-guidance failures with denominators, failed versus blocked/unverified verdicts, provider/provisioning interruptions, and measurement coverage; do not reinterpret historical scores.
- Ground context-file mappings and host extension claims in versioned primary sources. Identify documented capability separately from installation, runtime availability and observed execution; correct or qualify unsupported claims without installing context pointers or hooks.
- Extend native checks only for genuine documented validators and lifecycle operations applicable to each fixture. In particular, exercise OpenSpec publication/archive with independent pre-transition and surviving-evidence checks. Retain BMad regeneration and explicitly report unsupported or unavailable checks for the other hosts.
- Update the owning evaluation/install/candidate documentation and indexes as needed; keep the root README consistent with shipped behavior and preserve already completed block-6 items.

## Capabilities

### New Capabilities

None. Evaluation behavior remains within the existing agent-workflow boundary.

### Modified Capabilities

- `agent-workflow`: native measurement coverage, immutable cross-case reporting, and provenance-grounded applicable native verification.

## Impact

- Evaluation code: `evals/native-pilot.ts`, `evals/dialogue.ts`, `evals/acp-agent.ts`, existing measurement/result contracts, and a repository-only report entrypoint.
- Evidence: focused evaluator regressions and real disposable host/CLI executions. Planning records intended exact selectors; executable enrollment is deferred to apply.
- Documentation: `docs/development/agent-evals.md`, `docs/development/candidate-improvements.md`, and relevant installation/reference claims and indexes.
- No core CLI/API, SDK, installer destination, loader, portable guidance, approval, or sensitivity-policy change. Blocks 2 and 5 remain deferred, not cancelled; context-file installation remains conditional on measured need. No release or consumer integration refresh is implied.
